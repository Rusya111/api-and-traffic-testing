# Баг-репорты (Дефекты)

В ходе тестирования API и анализа трафика были выявлены следующие дефекты.

---

### BUG-001: Отсутствует обработка ошибки сервера (500) при авторизации
*   **Серьезность:** Minor
*   **Приоритет:** Medium
*   **Окружение:** Windows 11 / Charles Proxy
*   **Шаги воспроизведения:**
    1. Включить Breakpoint для `POST /login` в Charles.
    2. Выполнить вход на сайте.
    3. Подменить код ответа с 200 на 500.
*   **Фактический результат:** Сайт не выдает никаких сообщений об ошибке, интерфейс не реагирует на нажатие кнопки (сайт «зависает»).
*   **Ожидаемый результат:** Пользователь должен увидеть сообщение об ошибке (например, "Something went wrong" или "Server error"), либо кнопка входа должна вернуться в активное состояние.
*   **Ссылка на тест-кейс:** TC-014

---

### BUG-002: Отсутствует уведомление об ошибке при отсутствии токена авторизации
*   **Серьезность:** Minor
*   **Приоритет:** Medium
*   **Окружение:** Windows 11 / Charles Proxy
*   **Шаги воспроизведения:**
    1. Включить Breakpoint для `POST /login` в Charles.
    2. Выполнить вход на сайте.
    3. Удалить `Auth_token` из тела ответа.
    4. Нажать `Execute`.
*   **Фактический результат:** Сайт перезагружает главную страницу без предупреждения. Пользователь не понимает, почему вход не удался.
*   **Ожидаемый результат:** Должно появиться сообщение об ошибке авторизации (например, «Authorization failed»).
*   **Ссылка на тест-кейс:** TC-016
